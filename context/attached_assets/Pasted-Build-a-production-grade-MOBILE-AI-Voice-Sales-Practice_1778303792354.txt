Build a production-grade MOBILE AI Voice Sales Practice Application for Android (React Native Expo preferred).

This is NOT a web app.

The goal is to simulate realistic cold calling and sales conversations where users practice pitching web development, AI automation, and SaaS services to real-world customers.

The app must feel like a live phone call with human-like conversation behavior.

---

# CORE PURPOSE

The app helps users improve:
- Cold calling confidence
- Sales pitch structure
- Objection handling
- Real business conversation skills
- English speaking fluency (natural, not perfect grammar)

---

# TECH STACK (MOBILE ONLY)

Frontend:
- React Native (Expo)
- TypeScript
- Tailwind (NativeWind)
- Light/Dark mode support
- Fully mobile optimized UI

Backend:
- Node.js + Express (optional but recommended for AI routing)
- Modular architecture following SOLID principles

Database:
- SQLite (local mobile storage OR backend SQLite)
- Optional Supabase sync later

AI Layer (Multi Provider System):
- Google Gemini API (primary)
- Groq API (fast fallback)
- OpenRouter API (backup)

Voice System:
- Android Speech-to-Text (primary)
- Expo Speech / native TTS (text-to-speech)

---

# APP CORE IDEA

This is a REALISTIC AI CUSTOMER SIMULATOR.

The AI behaves like:
- business owners
- startup founders
- agency clients
- restaurant owners
- skeptical decision makers

It simulates real phone calls with objections, interruptions, and emotional responses.

---

# CONVERSATION ENGINE RULES

AI must:
- behave like a real human on a phone call
- avoid robotic or assistant-style answers
- mix short + medium-length responses naturally
- sometimes explain business context (budget, team, needs, issues)
- use real-world sales behavior
- interrupt or challenge user when needed
- show hesitation or interest realistically

---

# VOICE CONVERSATION FLOW

1. User speaks (speech-to-text)
2. System processes intent
3. AI generates response
4. Response is converted to voice automatically
5. Conversation continues like real call

Latency must be minimal (<2 seconds preferred).

---

# AI ROUTING SYSTEM

Implement fallback logic:

1. Try Gemini API first
2. If fail → Groq API
3. If fail → OpenRouter API
4. If all fail → use local DB scripted responses
